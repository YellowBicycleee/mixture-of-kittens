# EP8 MXFP8 backward: full-context forward and a fine backward ring

## Purpose and selected execution path

This optimization targets the routed MoE backward on EP8 with MXFP8 weights.
It separates two capacities that the legacy path ties together:

- `C` is the routed-row capacity allocated by forward for the retained context.
- `B` is the physical routed-gradient ring capacity used by backward.

For `B < C`, forward retains one complete context and backward selects
`dispatch_mlp_swiglu_combine_bwd_ep8_minibatch_full_context_no_replay_kernel`.
The backward ring is still reused at minibatch granularity, but later ring
generations read immutable saved activations instead of replaying routed
dispatch, Gate/Up GEMMs, and SwiGLU.

For `B = C`, the reported `NEW-selected` arm uses the exact `OLD-tuned`
configuration and legacy macrobatch path. This row is labeled
`legacy_terminal_fallback`. The fine-path tuning data remains in the raw JSON,
but it is not presented as the selected implementation. Because OLD and NEW
are separately timed invocations of identical code at this terminal row, any
small latency difference there is measurement noise rather than an algorithmic
difference.

## Execution flow and synchronization

The `ep8_full_context_fine` path performs the following work:

1. Forward runs with `macrobatch_size=C` and retains the routed MXFP8 `x`,
   Gate, Up, and `hidden` data and scales for every padded routed row.
2. Backward runs with `macrobatch_size=B`, `bwd_schedule="minibatch"`, and a
   legal tuned `minibatch_size`. Saved activations use global routed-row
   addresses; `dY`, `dHidden`, `dGate`, `dUp`, `dX`, and router-gradient
   staging remain B-sized and ring-addressed. Generation-indexed readiness
   and retirement counters still gate B-ring slot reuse. With replay compiled
   out, shared Wgrad reads the caller's local `x` directly and skips the
   otherwise-unused symmetric replay-buffer copy.
3. Router scores are gathered once into a full-context `float32[C]` cache.
   Communication CTAs for later generations still wait for the prior owner of
   each gradient-ring slot to retire; the cache does not remove that safety
   dependency.
4. Each routed weight-gradient owner covers one
   `(expert, macrobatch segment, matrix, output tile)` and keeps one FP32
   accumulator across its source minibatches. After the last K block of each
   reusable source-minibatch/expert intersection has been loaded, it sends a
   source-read notification; it commits once when the segment ends. Unsplit
   experts store directly; split experts use reduction-add after selective
   zeroing.
5. EP8/MXFP8 reverse-dispatch communication CTAs are the transitive sink for
   the non-Wgrad Dgrad-down, SwiGLU-backward, and Dgrad-Gate/Up chain. Wgrad
   source reads retain their separate completion counter before a ring slot is
   reusable.
6. Routed Dgrad task ownership uses an upper-bound lookup over the existing
   expert-row prefix. Qwen EP8 has 64 local experts, so the common lookup is six
   unrolled comparisons instead of a per-task linear expert scan.

Fine retirement changes when split-expert BF16 weight-gradient partials may be
added. The path is race-free, but it is not bitwise deterministic. The default
`bwd_schedule="macrobatch"` path retains its deterministic accumulation order.

## Memory tradeoff

The retained MXFP8 routed context allocates `7,392*C` bytes/rank across the
saved data and scale tensors, even when a rank's actual padded routed-row count
is below `C`. This excludes shared-expert context, backward-gradient rings,
weights, scratch tensors, and allocator overhead.

| workload | retained `C` | retained routed context/rank | full router-score cache/rank |
|:---|---:|---:|---:|
| Qwen 20K | 217,088 | 1,604,714,496 B (1.4945 GiB) | 868,352 B |
| Qwen 100K | 1,036,288 | 7,660,240,896 B (7.1342 GiB) | 4,145,152 B |

The full router-score cache is `4*C` bytes. Relative to a ring-local router
cache it adds `4*(C-B)` bytes; for the 100K workload at `B=131072`, that is
3,620,864 bytes/rank. The main cost is the retained routed activation context,
not the router cache.

`C` must cover the maximum expert-padded routed-row count across all EP ranks.
Each forward or backward `macrobatch_size` must also be a positive multiple of
the `minibatch_size` used by that call.

Every macrobatch row compares three arms:

- `OLD-default`: legacy macrobatch schedule using repository defaults
  `minibatch_size=4096`, `fwd_num_comm_sms=40`, and
  `bwd_num_comm_sms=28`, except that `macrobatch_size` is the row's `B`.
- `OLD-tuned`: legacy path with legal minibatch and communication-SM values
  tuned for that row.
- `NEW-selected`: `ep8_full_context_fine` for `B<C`, or the exact tuned legacy
  configuration at `B=C`.

The bounded sweep considers at most four representative legal minibatch
divisors. Communication-SM screening uses FWD
`{16,24,32,40,48}` and BWD `{28,40,50,54,56,62}`, then refines the two best
minibatches at communication-SM offsets `{-4,-2,0,2,4}`. OLD FWD and BWD and
NEW BWD are independently tuned. NEW FWD always executes with the same `C`
within a workload, so it is swept once per workload. For every row, each
implementation's direct FWD+BWD candidate is selected from its FWD top two
crossed with its independently tuned BWD top two. At `B=C`, the candidate NEW
selection is then replaced by the exact OLD-tuned terminal fallback.

Correctness uses inputs generated with `seed=1234+rank`. Each selected phase
and combined configuration checks the output and all eight returned gradients
against the preserved one-generation reference, with the repository MXFP8
limits `max_abs_error <= 1.0` and `relative_error <= 0.1`.

Final latency uses five warmup pairs and 20 timed pairs. Each sample is the
maximum CUDA-Event time across the eight ranks, and OLD/NEW order alternates
with the fixed baseline between them. The reported latency is the median of
those rank-max samples; paired median and p90 deltas are also retained. A
stable win requires both paired deltas to be below zero.

The timing boundaries are:

- FWD: one CUDA-Event interval around complete `functional.forward`.
- BWD: one CUDA-Event interval around complete `functional.backward`; its
  fresh preparation forward and schedule construction are excluded.
- FWD+BWD: one CUDA-Event interval around direct forward followed by backward;
  schedule construction is excluded.

FWD+BWD is measured directly. It is not computed by adding the standalone FWD
and BWD medians.

## Bandwidth definition

Bandwidth is a derived useful cross-GPU payload rate, not an NCU, HBM, NVLink
link-counter, or wire-rate measurement. For the aggregate number, let `R` be
the number of valid remote routes summed across the eight ranks and `H` the
hidden size:

- FWD useful bytes: `R * 4H`.
- BWD useful bytes: `R * (4H + 8)`.
- FWD+BWD useful bytes: the sum of the two expressions.
- Aggregate GB/s: `useful_bytes / (latency_ms * 1e6)`.
- Per-GPU GB/s: aggregate GB/s divided by eight.

The numerator excludes local routes, padded rows, replay traffic, and protocol
overhead. Speedup is reference median latency divided by NEW median latency.

## Complete results

Against the fixed `OLD-default`, `NEW-selected` is a stable paired win in all
48 of 48 macrobatch rows for each of FWD, BWD, and directly measured FWD+BWD.
Among the 23 fine-path rows per workload (excluding the `B=C` legacy terminal
fallback), stable wins versus independently tuned `OLD-tuned` are
FWD/BWD/FWD+BWD = 16/23, 23/23, and 23/23 for 20K, and 20/23, 23/23, and
22/23 for 100K.

workload-wide best OLD-tuned FWD+BWD median. For 100K, the first such row is
`B=516096`; no smaller 100K ring meets that goal. The 100K global NEW FWD best
is 30.813 ms versus the OLD-tuned global best of 30.505 ms, so the global
OLD-tuned FWD best is not surpassed.
